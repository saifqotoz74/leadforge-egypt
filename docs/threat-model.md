# LeadForge Egypt — Threat Model (`docs/threat-model.md`)

## 1. System Assets Under Protection
1. **Unclaimed Lead Contact Bundles**: Business phone numbers, secondary phones, emails, exact street addresses, and social/map links that constitute LeadForge Egypt's core monetized inventory.
2. **Developer Credit Ledgers & Claims**: `DeveloperCreditAccount` balances, `CreditTransaction` immutable ledger rows, and `LeadClaim` ownership records (Shared vs. Exclusive).
3. **Tenant Business Intelligence**: Developer-specific sales pipelines (`LeadEngagement`, `ContactAttempt`), win/loss notes, estimated project values, and developer analytics.
4. **Platform Decision Engines**: Deterministic Scoring Rules (`ScoringRule`), Matching Rules (`MatchingRule`), Quality/Freshness thresholds (`QualityConfig`, `FreshnessConfig`), and Credit Pricing (`CreditPricingConfig`).
5. **External Ingestion Infrastructure**: Collector credentials, source configurations (`LeadSource.config`), and outbound network fetchers.
6. **User Credentials & Sessions**: Password hashes (`User.passwordHash`), JWT signing secret (`JWT_SECRET`), and session cookies (`leadforge_session`).

---

## 2. Threat Actors
- **Unauthenticated External Attacker**: Attempts credential stuffing, registration spam, unauthenticated API access, or SSRF/injection attacks.
- **Malicious / Curious Developer (Authenticated Tenant)**: Attempts to extract unclaimed lead phone numbers without paying credits, double-spend credits via race conditions, access another developer's claims/engagements/analytics (IDOR), spoof feedback to trigger fraudulent refunds, or escalate privileges to `ADMIN`.
- **Compromised / Malicious External Data Source**: Serves malicious HTML/JSON payloads, CSV formula payloads, oversized responses, infinite redirect loops, or redirects pointing to internal cloud metadata (`169.254.169.254`) or localhost (`127.0.0.1`).
- **Careless / Compromised Admin Session**: Triggers concurrent duplicate ingestion jobs, uploads malformed/oversized CSV files, or exports large datasets.

## 3. Threat Matrix & Deterministic Mitigations

| Threat ID | Category | Attack Vector | Impact | Deterministic Mitigation Implemented | Verification Test |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **TM-01** | **Lead PrivacyLeakage** | Developer queries `/api/leads`, `/api/leads/[id]`, `/api/matching/**`, or `/api/leads/[id]/verification` to harvest unmasked phones/emails without claiming. | Loss of marketplace revenue; inventory scraping. | Server-side `formatLeadForResponse` & `redactSensitiveSummary` mask all contact fields unless an active `LeadClaim` exists for `user.id` or `user.role === 'ADMIN'`. | `phase5-claims-credits.test.ts`, `phase9-security-performance-reliability.test.ts` |
| **TM-02** | **Exclusive Claim Race Condition** | 20 developers concurrently send `POST /api/leads/[id]/claim` for the same `EXCLUSIVE` lead. | Multiple developers charged and granted exclusive ownership. | In-process deterministic lock (`withResourceLocks`) + PostgreSQL `SELECT ... FOR UPDATE` row locks + partial unique index `LeadClaim_exclusive_active_leadId_key` + `Lead_purchasers_check` constraint. Exactly 1 succeeds (`200`); 19 receive `409 CONFLICT`. | `phase5-claims-credits.test.ts`, `phase9-security-performance-reliability.test.ts` |
| **TM-03** | **Shared Lead Over-Selling** | 20 developers concurrently claim a `SHARED` lead with `maxPurchasers = 3`. | More than 3 developers purchase the lead. | Row-level lock on `Lead` + atomic check `currentPurchasers < maxPurchasers` + PostgreSQL constraint `CHECK ("currentPurchasers" <= "maxPurchasers")`. Exactly 3 succeed. | `phase9-security-performance-reliability.test.ts` |
| **TM-04** | **Credit Double-Spend Race** | Developer with balance only sufficient for 1 claim sends 10 parallel claim requests for different leads. | Negative credit balance; free leads claimed. | Deterministic lock on `account:<developerId>` + `SELECT ... FOR UPDATE` on `DeveloperCreditAccount` + PostgreSQL `CHECK ("balance" >= 0)` and `CreditTransaction_ledger_math_check`. | `phase5-claims-credits.test.ts`, `phase9-security-performance-reliability.test.ts` |
| **TM-05** | **Cross-Tenant IDOR** | Developer A accesses Developer B's claim, engagement status, contact attempts, match explanation, or cached analytics. | Unauthorized disclosure or modification of competitor pipeline. | Strict server-side ownership check (`claim.userId === user.id`) + `TenantAwareCache` runtime `tenantDeveloperId` verification + `IDOR_PROBE_DETECTED` security signal. | `phase6-feedback-outcomes.test.ts`, `phase9-security-performance-reliability.test.ts` |
| **TM-06** | **Privilege Escalation & Mass Assignment** | Developer sends `role: "ADMIN"`, `balance: 99999`, or `passwordHash` in `PATCH /api/developer/profile` or registration. | Unauthorized admin access or free credit minting. | Explicit field allowlisting in route handlers + `detectForbiddenFieldsInPayload` guard. | `phase9-security-performance-reliability.test.ts` |
| **TM-07** | **SSRF & DNS Rebinding** | Attacker supplies `http://127.0.0.1`, `http://169.254.169.254/latest/meta-data/`, `http://[::1]`, or a domain resolving/redirecting to a private IP in website collector or live verification. | Cloud metadata credential theft or internal network scanning. | `assertSafeExternalUrlWithDns` + `safeExternalFetch` block private/loopback/link-local IPv4 & IPv6 literals, validate DNS-resolved IPs, and revalidate every HTTP redirect hop. | `phase8-ingestion-collectors.test.ts`, `phase9-security-performance-reliability.test.ts` |
| **TM-08** | **CSV Formula Injection & Malicious Upload** | Attacker imports or exports business names starting with `=CMD\|...`, `+SUM(...)`, `-2+3`, `@SUM(...)`, `\t=1+1`, or uploads `.exe`/`.html` files. | Client-side RCE/data exfiltration when admin opens CSV in Excel; server DoS. | `validateImportUploadSafety` blocks dangerous extensions/MIMEs and oversized payloads; `sanitizeSpreadsheetFormula` and `escapeCsvCell` neutralize formula prefixes on import and export. | `phase8-ingestion-collectors.test.ts`, `phase9-security-performance-reliability.test.ts` |
| **TM-09** | **Feedback / Refund Abuse** | Developer repeatedly submits false `INVALID_PHONE` feedback to farm automatic credit refunds. | Financial loss and inventory poisoning. | Phase 5 refunds require explicit Admin review or deterministic multi-signal verification; Phase 6 `evaluateDeveloperAbuseSignals` flags high invalid-report rates without auto-corrupting canonical leads. | `phase6-feedback-outcomes.test.ts`, `phase9-security-performance-reliability.test.ts` |
| **TM-10** | **Information Disclosure via Error / Logs** | Triggering malformed queries or internal exceptions to leak stack traces, SQL queries, file paths, or `passwordHash`. | Aids reconnaissance and credential compromise. | `createSafeErrorResponse` & `redactSensitiveData` scrub stack traces, SQL, paths, and secret keys; `PATCH /api/admin/users` explicitly projects safe fields excluding `passwordHash`. | `phase9-security-performance-reliability.test.ts` |
